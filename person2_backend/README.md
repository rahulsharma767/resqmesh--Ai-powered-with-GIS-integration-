# ResQMesh AI — Backend, GIS, Routing & Local AI

This service is the operational core of ResQMesh AI. It combines the existing Mumbai road graph, deterministic ambulance/hospital selection, closure-aware A* routing, simulated live state, and the new local emergency-risk model.

## Services

- `POST /api/ai/analyze` — local risk/priority/confidence inference.
- `GET /api/ai/status` — actual model/runtime/provider status.
- `POST /api/v1/emergency/dispatch` — deterministic ambulance + hospital + route decision.
- `GET /api/v1/ambulances` — simulated fleet state.
- `GET /api/v1/hospitals` — hospital directory + simulated live state.
- `POST /api/v1/roads/closures` — close a directed graph edge for simulation.
- `POST /api/v1/roads/reroute` — compute a route avoiding active closures.
- `PATCH /api/v1/hospitals/{id}/state` — update simulated hospital state.

## AI engine

`ai_engine/` contains a real trained tabular classifier. The checked-in artifacts are:

- `models/emergency_risk_model.npz` — portable learned parameters used by the local fallback.
- `models/emergency_risk_model.onnx` — ONNX representation of the same model.
- `model_metadata.json` — feature/model metadata.
- `MODEL_CARD.md` — limitations and deployment notes.

The model uses synthetic simulation data generated by `scripts/train_risk_model.py`; this is explicitly not clinical data.

Runtime preference:

```text
ONNX model → ONNX Runtime → QNNExecutionProvider (if actually available)
                           → CPU/local fallback otherwise
```

`/api/ai/status` is authoritative. The backend never labels a fallback run as Snapdragon NPU execution.

## Setup

```powershell
cd person2_backend
python -m pip install -r requirements.txt
```

The repository includes the processed Mumbai road node/edge CSVs. For a fast local startup, the final submission package may also contain `data/processed/mumbai_road_graph.pkl`. The pickle is intentionally ignored by `.gitignore` because it is ~138 MB; if it is absent, the router automatically rebuilds the NetworkX graph from the processed CSVs.

## Run

```powershell
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Health: `http://127.0.0.1:8000/health`

## Test

```powershell
python tests/test_ai_engine.py
python tests/test_dispatch_demo.py
```

The dispatch test exercises the real Mumbai graph and deterministic ambulance/hospital selection. The AI test verifies the checked-in local model and runtime status contract.

## Data boundary

**Real/reference inputs:** OSM-derived Mumbai road graph and the included hospital directory data.

**Simulated:** ambulance movement/live GPS, traffic schedule, hospital live capacity state and other operational events. The UI labels these layers explicitly.

## Safety boundary

The AI risk engine is advisory. It does not select or override an ambulance, route or hospital. Deterministic operational checks remain authoritative, and the final workflow is intended for human approval.
